# Pet Monitor

A small IoT companion for keeping track of day-to-day pet care.

Pet Monitor helps everyone caring for a pet stay in sync. Record simple care events—such as feeding or giving medication—and see which events have already happened. Events can be entered through the web application and synchronized to the Pet Monitor device, so the people sharing pet-care duties have a common view of the latest activity.

## Why Pet Monitor?

When several people look after the same pet throughout the day, it is easy to forget whether food or medication has already been given. Pet Monitor is intended to make those handovers simpler by keeping pet-care events visible in one place.

## Features

- **Pet-care event tracking:** record everyday events such as feeding and medication.
- **Shared history:** give caregivers a common record of care activities.
- **Cloud synchronization:** events recorded in the web application are reflected on the IoT device.
- **At-a-glance device interface:** use the compact touch display to review pet-care information.
- **Designed for a small embedded device:** runs on the Waveshare ESP32-S3-Touch-LCD-1.69 development board.

> The exact event types, offline behavior, conflict handling, and synchronization guarantees depend on the application implementation.

## Graphical user interface (GUI)

The device GUI is built with **EEZ Studio Flow v0.29.0** and **LVGL v8.4.0**. The generated GUI sources are copied into the application's `src/gui/` subfolder.

### Generated GUI sources and application integration

- `src/gui/` contains the GUI source files generated by EEZ Studio.
- `src/gui/actions.c` must be implemented for this application. It provides the application-specific behavior for the **User Actions** defined in the EEZ Studio project.
- `src/gui/vars.c` must be implemented for this application. It connects the GUI's global variables to the application's state and data.

EEZ Studio-generated code is the starting point for the interface, but the application-specific implementations of `actions.c` and `vars.c` are responsible for integrating the GUI with Pet Monitor's event data, cloud synchronization, and device behavior.

### GUI development workflow

1. Design or update the screens, global variables, and **User Actions** in EEZ Studio Flow v0.29.0.
2. Generate the GUI code for LVGL v8.4.0.
3. Copy the generated GUI sources into `src/gui/`.
4. Implement or update `src/gui/actions.c` to handle the generated User Actions.
5. Implement or update `src/gui/vars.c` to map and update the GUI global variables.
6. Build and test the application on the ESP32-S3 target, checking that GUI actions and displayed values remain consistent with the pet-care event data and synchronization state.

### Important maintenance notes

- Treat the EEZ Studio project as the source of truth for generated screens, global variables, and User Actions.
- Avoid making manual changes to generated files unless the generation workflow explicitly requires them; manual changes may be overwritten when code is regenerated.
- After changing global variables or User Actions in EEZ Studio, review `actions.c` and `vars.c` and update their implementations to match.
- Keep application logic—such as recording feeding or medication events and handling cloud updates—connected through the application-specific integration code rather than relying on generated GUI code alone.

## How it works

At a high level, Pet Monitor has two interfaces connected through a cloud service:

1. **Web application:** a caregiver records a pet-care event in the cloud.
2. **Cloud service:** stores and makes the event available to the device and other caregivers.
3. **Pet Monitor device:** synchronizes events and presents them on the ESP32-S3 touch display.

This shared record helps caregivers answer a practical question before acting: *Has this care event already been done?*
